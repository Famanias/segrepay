💡
Strategy: Build the smart contract first and get it deployed in the first 2 hours. Everything else (frontend, QR, leaderboard) is just a UI on top of a working contract. If the contract is live and callable, your demo works even if the UI is rough.
⚠️
What we're cutting: No real IoT QR scanning, no token redemption marketplace, no barangay admin authentication. Those are V2. For the demo, we simulate the EcoVerifier role from a second MetaMask wallet and generate QR codes statically. Judges care about the blockchain working — not the UI being pixel-perfect.

// 01 · Team Setup

Who Does What

👥
Ideal team: 3–4 people. Split into two tracks that run in parallel from Hour 2 onward — Blockchain Track and Frontend Track. They only merge at Hour 7 during integration. This is how you hit 11 hours without crunch-killing yourself.

Blockchain Dev

1–2 people · BC Track

  • Write SegreToken.sol (ERC-20)
  • Write SegRewards.sol (deposit + reward logic)
  • Deploy both contracts on Fuji testnet via Remix or Hardhat
  • Copy & share contract ABI + addresses to frontend team
  • Write contract interaction scripts for demo fallback
  • Test all contract functions end-to-end

Frontend Dev

1–2 people · FE Track

  • Scaffold React + Vite project
  • Implement MetaMask / Core Wallet connection
  • Build Verifier deposit form (UI only, then hook to contract)
  • Build Citizen dashboard (token balance display)
  • Build barangay leaderboard from contract events
  • Generate static QR codes for demo households

Project Lead / Presenter

1 person · ALL

  • Manage timeline and keep both tracks unblocked
  • Document the problem-solution narrative
  • Prepare presentation slides (5-min format)
  • Write the demo script and rehearse it
  • Handle testnet AVAX faucet top-ups
  • QA test the full user flow before judging

// 02 · Core Features

The 4 Things We Ship. Nothing Else.

🚫
Scope discipline is everything in a hackathon. Every feature below is load-bearing for the demo. If it's not in this list, it does not get built today. No exceptions.
01

ECO Token on Avalanche (ERC-20)

A mintable ERC-20 token deployed on Avalanche Fuji Testnet. The SegRewards contract is the only authorized minter. This is the core economic primitive — every reward flows through it. No token = no demo. This must be deployed and verified in the first 90 minutes.

Hrs 0–1.5
BC
02

EcoVerifier Deposit Panel

A simple form — barangay selector, waste category (biodegradable / recyclable / residual), weight in kg, and citizen wallet address — that a designated EcoVerifier wallet submits to the rewardDeposit() contract function. On success, ECO tokens are minted to the citizen's address. This is the core value transaction of the entire system.

Hrs 2–5
FE
03

Citizen Wallet Dashboard

A wallet-connected view that shows: (a) the connected address, (b) current ECO token balance fetched live from the contract, and (c) a transaction history of deposits received. No redemption flow needed today — just proof that tokens land in the right wallet and the balance updates in real time after a deposit.

Hrs 3–5
FE
04

Live Barangay Leaderboard

A ranked table of barangay names and their cumulative ECO tokens earned, pulled from on-chain DepositLogged events. Refreshes every 15 seconds or on each new deposit. This is the visual money shot for judges — they can see Barangay 1 climbing the leaderboard in real time as you demo a deposit. Pre-load 3 demo barangays with simulated on-chain history before the presentation.

Hrs 5–7
FE

// 03 · Tech Stack

Every Tool, Why We're Using It

Tool / Library Layer What It Does in SegrePay Why Not Something Else
Solidity 0.8.x BC Smart contract language. Writes both SegreToken.sol and SegRewards.sol. Avalanche C-Chain is EVM-compatible. Solidity is the only practical choice for a hackathon timebox.
Remix IDE BC Browser-based Solidity IDE. Write, compile, and deploy directly to Fuji testnet without any local setup. Zero setup time. Hardhat is more powerful but takes 30–45 min to configure. We don't have that time.
OpenZeppelin Contracts BC Use ERC20.sol and Ownable.sol as base classes. Don't write ERC-20 from scratch. Battle-tested, audited code. Using it means 90% of the token contract is already written — just inherit and extend.
Avalanche Fuji Testnet BC Free testnet environment. Deploy contracts, call functions, and show real blockchain transactions — no real money needed. Avalanche C-Chain is required by the hackathon. Fuji is its official testnet. AVAX faucet gives free test tokens in seconds.
Core Wallet / MetaMask BC Browser wallet for signing transactions. Use Core Wallet (native Avalanche) for judging demo; MetaMask as fallback. Core Wallet is built by Ava Labs — using it signals you know the Avalanche ecosystem. Bonus impression points with judges.
React + Vite FE Frontend framework and dev server. Fast HMR, instant scaffolding with npm create vite@latest. Fastest setup for a React project. Zero config. The entire team likely knows it already.
Ethers.js v6 FE Connects the React frontend to the Avalanche contracts. Handles wallet connection, contract calls, and event listening. Industry standard for EVM frontends. Web3.js is heavier. Ethers.js has cleaner async API and better error messages.
Tailwind CSS FE Utility-first CSS. Style the deposit form, dashboard, and leaderboard without writing a single CSS file. Fastest way to get a presentable UI in a hackathon. No naming classes, no context switching.
qrcode.react FE Generate printable QR codes from wallet addresses. In the demo, each "household" has a QR that encodes their AVAX wallet address. One-line install (npm i qrcode.react), zero config, renders as SVG. 10 minutes to implement.
Recharts FE Render the barangay leaderboard as a live bar chart in addition to the table. Judges love a chart that moves. React-native charting, 5-minute integration, no D3 complexity. Pre-built bar chart component works out of the box.

// 04 · Smart Contracts

The Exact Code to Write

📋
Copy this into Remix and deploy. These are complete, production-ready contracts for the MVP. The blockchain dev should be able to have both deployed within 90 minutes of the hackathon starting — including testnet AVAX faucet setup.
SegreToken.sol Avalanche Fuji C-Chain · Solidity ^0.8.20
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@openzeppelin/contracts/token/ERC20/ERC20.sol"; import "@openzeppelin/contracts/access/Ownable.sol"; /** * @title SegreToken * @notice The SegrePay reward token. Only the SegRewards contract * (set as owner after deployment) can mint new tokens. */ contract SegreToken is ERC20, Ownable { constructor() ERC20("SegrePay Token", "ECO") Ownable(msg.sender) {} /// @dev Called by SegRewards contract only function mint(address to, uint256 amount) external onlyOwner { _mint(to, amount); } }
SegRewards.sol Avalanche Fuji C-Chain · Solidity ^0.8.20
// SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@openzeppelin/contracts/access/Ownable.sol"; import "./SegreToken.sol"; /** * @title SegRewards * @notice Core logic for SegrePay. * Verifiers submit waste deposits → citizens earn ECO tokens. * All deposits are permanently logged on-chain. */ contract SegRewards is Ownable { SegreToken public segreToken; // Tokens minted per kilogram of waste deposited uint256 public tokensPerKg = 10 * 1e18; // 10 ECO per kg // Approved verifier wallets (barangay MRF operators) mapping(address => bool) public isVerifier; // Track each barangay's total ECO minted (1–17 for Olongapo) mapping(uint8 => uint256) public barangayTotal; // Track each citizen's cumulative kg deposited mapping(address => uint256) public totalKgDeposited; // ── Events (queried by frontend for leaderboard) ── event DepositLogged( address indexed citizen, uint8 barangayId, string wasteCategory, // "biodegradable" | "recyclable" | "residual" uint256 kg, uint256 ecoMinted, uint256 timestamp ); event VerifierUpdated(address verifier, bool status); // ── Constructor ── constructor(address _segreToken) Ownable(msg.sender) { segreToken = SegreToken(_segreToken); } // ── Admin: add/remove verifier wallets ── function setVerifier(address v, bool status) external onlyOwner { isVerifier[v] = status; emit VerifierUpdated(v, status); } // ── Admin: adjust reward rate ── function setTokensPerKg(uint256 amount) external onlyOwner { tokensPerKg = amount; } /** * @notice Verifier calls this after physically confirming a * citizen's waste deposit at the MRF. * @param citizen Wallet address of the depositing household * @param barangayId Barangay number (1–17) * @param wasteCategory Type of waste segregated * @param kg Weight of deposit in kilograms */ function rewardDeposit( address citizen, uint8 barangayId, string calldata wasteCategory, uint256 kg ) external { require(isVerifier[msg.sender], "Not an authorized verifier"); require(kg > 0, "Weight must be > 0 kg"); require(citizen != address(0), "Invalid citizen address"); uint256 reward = kg * tokensPerKg; // Update state barangayTotal[barangayId] += reward; totalKgDeposited[citizen] += kg; // Mint tokens directly to citizen wallet segreToken.mint(citizen, reward); emit DepositLogged( citizen, barangayId, wasteCategory, kg, reward, block.timestamp ); } /// @notice Read barangay totals for the leaderboard function getBarangayTotals(uint8[] calldata ids) external view returns (uint256[] memory totals) { totals = new uint256[](ids.length); for (uint i = 0; i < ids.length; i++) { totals[i] = barangayTotal[ids[i]]; } } }
🚀
Deployment order: (1) Deploy SegreToken.sol → copy the deployed address. (2) Deploy SegRewards.sol passing the SegreToken address as constructor argument. (3) Call SegreToken.transferOwnership(SegRewards_address) so the rewards contract can mint. (4) Call SegRewards.setVerifier(yourWallet, true) to authorize the demo verifier wallet.

// 05 · Hour-by-Hour Timeline

The Full Day, Mapped Out

⏱
Time check rule: At the end of every phase, the team lead does a 5-minute sync. If any track is more than 45 minutes behind, immediately cut scope — never push demo prep past the 10-hour mark.
Hour
0 – 0:30
⚙️ Setup Pre-Flight Check — Everyone Together
  • ALL Install Core Wallet browser extension on the demo laptop. Add Avalanche Fuji Testnet manually (Chain ID: 43113, RPC: https://api.avax-test.network/ext/bc/C/rpc). Go to faucet.avax.network and claim 2 AVAX for each wallet you need (admin, verifier, 3 citizen demo wallets).
  • ALL Open Remix IDE in the browser (remix.ethereum.org). Create two files: SegreToken.sol and SegRewards.sol. Paste the contract code in. Connect Remix to Core Wallet on Fuji.
  • FE Run npm create vite@latest SegrePay -- --template react then npm install ethers qrcode.react recharts tailwindcss and initialize Tailwind. Make sure the dev server runs at localhost:5173.

Goal: Everyone has working wallets with testnet AVAX, Remix is open with contracts pasted, and the React project runs. Don't move on until this is done.

Hour
0:30 – 2
🔗 Blockchain Deploy Both Contracts to Fuji Testnet
  • BC In Remix, compile SegreToken.sol (compiler: 0.8.20, optimization: ON). Switch environment to "Injected Provider — Core Wallet". Deploy SegreToken. Copy the deployed contract address immediately and save it somewhere safe.
  • BC Compile and deploy SegRewards.sol, passing the SegreToken address as the constructor argument. After deployment, call SegreToken.transferOwnership(SegRewards_address) to hand minting authority to the rewards contract.
  • BC In the SegRewards contract on Remix, call setVerifier(your_demo_verifier_wallet, true). Then call rewardDeposit(citizen_address, 1, "recyclable", 2) as a smoke test. Check the citizen wallet's ECO balance — should show 20 ECO (2 kg × 10 ECO/kg). If this works, the contract is live.
  • BC Share both contract addresses and their ABIs (copy from Remix "Compilation Details" panel) in the team chat. The FE track needs these immediately.

🎯 Exit criteria: Both contracts deployed, smoke test passes, addresses + ABIs shared to FE. Verify on testnet.snowtrace.io — paste the contract address and confirm it shows the DepositLogged event from the smoke test.

Hour
2 – 4
⚛️ Frontend Wallet Connection + Verifier Deposit Form
  • FE Create src/hooks/useWallet.js. Use ethers.BrowserProvider(window.ethereum) to connect Core Wallet. Expose { address, signer, provider, connect }. Test by showing the connected wallet address on screen.
  • FE Create src/contracts/index.js. Export two contract instances initialized with Ethers: getSegreToken(signer) and getSegRewards(signer) using the ABIs and deployed addresses shared by the BC team. This is the single source of truth for all contract calls.
  • FE Build the VerifierPanel component. It's a simple form: dropdown for barangay (Barangay 1–3 for demo), dropdown for waste category, number input for kg, text input for citizen wallet address. On submit, call segRewards.rewardDeposit(citizen, barangayId, category, kg) with the connected verifier wallet and await tx.wait(). Show a success message with the transaction hash.
  • FE Add loading state and error handling to the form. If the wallet isn't a verifier, the contract will revert — catch this and show "Wallet not authorized as verifier" to the user instead of a raw error.

🎯 Exit criteria: Connect wallet button works. Verifier form submits a transaction, waits for confirmation, and shows a success state with a Snowtrace link. The BC team should verify the DepositLogged event appeared on-chain.

Hour
4 – 6
⚛️ Frontend Citizen Dashboard + Leaderboard
  • FE Build the CitizenDashboard component. Read the ECO token balance with segreToken.balanceOf(address) and display it formatted (divide by 1e18). Set up a 15-second polling interval using useEffect so the balance auto-refreshes after a deposit. Also display the wallet address and total kg deposited from segRewards.totalKgDeposited(address).
  • FE Build the Leaderboard component. Call segRewards.getBarangayTotals([1,2,3]) to get the 3 demo barangay totals. Render as a ranked table (name, ECO total, rank medal). Use Recharts BarChart to also show these as a horizontal bar chart with green bars. Refresh every 15 seconds.
  • FE Add a QR code section using qrcode.react. For the demo, generate 3 static QR codes hardcoded to the 3 pre-funded citizen wallet addresses. Label them "Household A / Barangay 1", etc. This represents how a real deployment would assign QR-linked eco-bags to households.
  • BC While FE works on the dashboard, seed the demo state: call rewardDeposit 5–6 times across the 3 demo barangays and 3 citizen wallets with varying kg values. This pre-populates the leaderboard with real on-chain history so it doesn't look empty during the demo.

🎯 Exit criteria: Citizen dashboard shows live ECO balance. Leaderboard shows 3 barangays with real on-chain data. QR codes display and look clean. The full flow — deposit via Verifier Panel → Citizen Dashboard balance updates → Leaderboard ranking changes — works end-to-end.

Hour
6 – 8
🔌 Integration Assembly, Layout & Bug Fixes
  • ALL Assemble the full app layout. Suggested page structure: top navbar with SegrePay logo + connected wallet address. Two-tab view: Tab 1 = "Verifier Panel" (the deposit form), Tab 2 = "Citizen View" (dashboard + leaderboard). QR codes shown in a side panel or modal.
  • ALL Run the full demo flow 3 times in a row from scratch: connect wallet → switch to verifier wallet → submit deposit → watch citizen balance update → watch leaderboard reorder. Fix any bugs found. Each full run should take under 2 minutes.
  • FE Add a "Recent Transactions" feed component. Query the SegRewards contract for DepositLogged events from the last 50 blocks using provider.queryFilter(). Display as a scrolling list: "Household [address] deposited Xkg of recyclables — earned Y ECO [time ago]". This shows judges the live blockchain feed.
  • ALL Polish visual pass: make sure fonts are readable, buttons have hover states, the leaderboard rankings are clearly numbered, and the Snowtrace transaction link opens correctly. It doesn't need to be beautiful — it needs to be legible and functional during a 5-minute presentation.

🎯 Exit criteria: One clean full-demo run with zero bugs, zero console errors visible on screen. The Snowtrace link for the last transaction opens and shows the DepositLogged event correctly decoded.

Hour
8 – 10
🎤 Demo Prep Presentation, Slides & Rehearsal
  • ALL Build the 5-minute slide deck (Google Slides or Canva). Sections: Problem (30 sec) → Solution (45 sec) → How Avalanche is used (45 sec) → Live demo (2 min) → Impact & next steps (1 min). Keep slides minimal — the demo is the main event.
  • ALL Rehearse the demo live at least twice. The demo script: (1) Open the app, show wallet connected. (2) Scan/show a QR code for "Household A". (3) Submit a deposit from the Verifier Panel. (4) Switch to Citizen tab — show balance going up live. (5) Show leaderboard reordering. (6) Click Snowtrace link to show the on-chain transaction. Time it — must fit in 2 minutes.
  • ALL Prepare a fallback plan: if internet is unstable during the live demo, have screenshots and a screen-recorded video of the working demo ready as backup. Also save the Snowtrace links to specific transactions in a browser bookmark for quick access.
  • ALL Top up all wallets via faucet one more time. Confirm the verifier wallet has enough AVAX to pay for 5–10 more transactions during the actual presentation. Testnet AVAX gas costs ~0.001 AVAX per tx — so 0.1 AVAX is more than enough.

🎯 Exit criteria: Clean 5-minute run-through from slides to demo to close. Backup video ready. All wallets topped up. Team knows who speaks which section.

Hour
10 – 11
💤 Buffer Contingency Time — Use Only If Needed
  • ALL This hour is intentionally held in reserve. If everything is done early, use it to add one bonus feature: a simple "Redeem ECO" form that calls a placeholder function (it can just log to console — the point is showing judges the redemption pathway exists). Or spend it polishing the UI color theme and typography.
  • ALL If you're behind, use this time to finish integration and bugfixes — not to add new features. A working 4-feature app beats a buggy 6-feature app every single time in a hackathon.

Final check: App is deployed and accessible via localhost (or deployed to Vercel in 5 min with npm run build && vercel deploy). Judges can access it on their own device if needed.

// 06 · Presentation

The 5-Minute Demo Script

  • 1

    Open with the problem — make it local and real (30 sec)

    "Olongapo's Solid Waste Management plan has been stuck in national review because it's missing household-level compliance data. Every uncollected bag of mixed waste that ends up in a drainage canal makes flooding worse for families in Sta. Rita and Gordon Heights. SegrePay fixes this — and it pays people to do it."

  • 2

    Explain the system in one sentence (20 sec)

    "Residents bring sorted waste to the MRF. A trained EcoVerifier scans their household QR bag and logs the deposit on the Avalanche blockchain. The smart contract automatically sends ECO tokens to the household's wallet. Every transaction is public, permanent, and tamper-proof."

  • 3

    Show the QR code and explain its role (15 sec)

    Hold up the printed QR code card. "This is Household A's eco-bag tag — the QR encodes their wallet address. The MRF operator scans it to pre-fill the citizen address field. No app needed on the citizen side."

  • 4

    Live demo: submit a deposit on Avalanche (90 sec)

    Switch to the live app. "I'm now logged in as the EcoVerifier wallet." Fill in: Barangay 1, Recyclable, 3 kg, paste Household A's wallet address. Click Submit — MetaMask/Core pops up, confirm. "The transaction is being confirmed on Avalanche — 2-second finality." Switch to the Citizen tab. "Household A's balance just went from X to Y ECO — live, on-chain." Switch to the Leaderboard. "Barangay 1 just moved up. Every deposit, every barangay, every token — permanently recorded on the blockchain." Click the Snowtrace link. "This is the on-chain proof — the DepositLogged event, timestamped, with the barangay, waste category, kg, and ECO minted. Immutable."

  • 5

    Close with impact and scalability (45 sec)

    "This on-chain ledger is exactly the compliance data Olongapo's SWM plan needs to get national approval. ECO tokens become exchangeable for city fee discounts or partner rewards — building a circular local economy. And because this is on Avalanche, it can scale to any of the 352 cities in the Philippines with the same SWM data problem. SegrePay — where every bag of properly sorted waste becomes a block on the chain."

// 07 · Risk Register

What Could Go Wrong & How to Handle It

Risk Likelihood Mitigation
Fuji testnet is slow or congested during demo Medium Have 3 pre-confirmed transactions bookmarked on Snowtrace as backup. If live tx is slow, show the bookmark and say "here's a previous transaction from our testing — same output." Video backup also works.
Core Wallet / MetaMask fails to pop up during demo Medium Test on the exact demo laptop 30 min before presentation. Have a second laptop ready with wallets pre-configured. Refresh the page if the extension freezes — it usually recovers.
Faucet rate limit — wallets run out of testnet AVAX Low Request faucet AVAX at the start of the hackathon and again at Hour 8. 0.5 AVAX per wallet is sufficient for 50+ transactions. Keep 3 backup wallets ready with AVAX.
Smart contract bug discovered during integration Medium Redeploy is fast (under 5 min on Remix). Don't spend more than 20 minutes debugging — redeploy with a fix. Keep the old contract address noted in case the new deploy has issues.
Frontend Ethers.js connection breaks in build Low Run the demo from the Vite dev server (npm run dev), not a production build. Avoids most build-time issues. If deploying to Vercel, test the deployed URL immediately after pushing.
Team member falls behind, blocking the critical path High if unmanaged Project lead checks in every 90 minutes. If FE is blocked on contract integration, BC team drops everything and pair-programs with them. The leaderboard is the lowest-priority feature — cut it last if time is short. The core demo only needs the deposit form + citizen balance.
